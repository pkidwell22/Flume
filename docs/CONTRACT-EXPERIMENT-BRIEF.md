# Contract experiment brief

**Status: archived direction, not an instruction to start execution.** Patrick posted the text below for posterity. It is preserved verbatim; implementation, installation, paid calls, and publication remain subject to the stated authorization boundaries.

---

Deepen our foundation work by proving one representative agent-directed production workflow. Do not broaden the competitor list, add features, replace the selected stack, or produce more architecture prose without resolving a concrete uncertainty.

Use this workflow:

An agent prepares a shot with explicit first/last-frame bindings and recorded continuity provenance; a human reviews and authorizes the exact request; generation executes asynchronously; the application recovers from interruption; the result becomes an owned alternative that is selected explicitly.

First, identify the assumptions in that workflow that are expensive to reverse or dangerous to get wrong. Turn them into explicit preconditions, state transitions, authority boundaries, and testable invariants. Distinguish editable plans and drafts, frozen generation specifications, authorized attempts, worker deliveries, output assets, and editorial selections.

Work from primary material. Use REA MCP and controlled observation to trace relevant Higgsfield behavior. Inspect Slop Cannon’s official agent contracts and Studio’s actual source contracts. Use exact Comfy route schemas and real input/output media where authorized. Preserve source versions and evidence locations. Separate documented behavior, static wiring, observed execution, and our proposed design; do not infer a backend from frontend code or treat a prototype as production.

Build a disposable contract experiment, not product scaffolding, using the selected stack where needed. Prove the difficult boundaries with real PostgreSQL/Drizzle/pg-boss transactions and actual media processing. Use controlled provider fixtures for failure injection, clearly labeled as simulations.

Challenge at least these cases: concurrent human edits, stale agent commands, lost submission responses, worker restart after possible provider acceptance, cancellation racing with completion, duplicate delivery/import, late frame extraction, and selection changes during export.

For each case, define the expected result before running it. Retain reproducible test commands, fixture identities, traces, database assertions, and media measurements. A test must establish the relevant invariant—not merely show that a function returned successfully.

Do not install software, upload private media, spend credits, change live services, or publish anything without the required authorization. If a real-provider check is necessary, specify the smallest test, its data transfer, and its spending limit. If access is blocked, report the exact unresolved claim rather than substituting plausible output.

Finish with:

A concise evidence-backed behavioral contract.
Results showing what passed, failed, or remains untested.
The smallest architecture that satisfies the proven requirements, with each important boundary tied to a failure it prevents.
Corrections to our existing spec—especially assumptions we should discard.
An independent review of the contracts and evidence.
Optimize for maintainability, inspectability, and truthful recovery. Preserve the creative controls and agent-director experience. The goal is not the most elaborate architecture; it is a foundation whose important claims we can demonstrate.
